# I-3 프로필 기반 변환

상태: **승인됨(2026-10-15), 구현 완료(PR 검토 중).** D1~D10 권장안으로 확정, 보완 2건 반영(아래). I-2(프로필 형식 v1)는 PR #4로 `main`에 병합됐다([I-2-profile-v1.md](I-2-profile-v1.md)). 단계 표: [roadmap.md](../roadmap.md).

## 목표
변환을 **프로필로 구동**한다. 코드에 박힌 유스케이스 전용 로직(`FIELD_MAP`, 라벨, `UseCaseItem`, 흐름 번호, 첫 번째 표)을 없애고, 프로필만 바꿔 다른 매핑을 쓸 수 있게 한다. 검증된 kind(`fields`·`cells`·`repeat`(table)·`diagrams`)만 연결한다. **유스케이스 변환 결과는 이전과 같아야 한다**(동작 보존).

## 바뀌는 것

| 지금(I-1·I-2) | I-3 이후 |
|---|---|
| `parseMarkdown`이 유스케이스 구조(`UseCaseItem`: fields/flows/diagrams)를 고정으로 읽음 | **프로필의 `md`로 구동하는 일반 파서**: 컬렉션·슬롯 → 일반 데이터 트리(캡처, 슬롯 값, 줄 번호, 하위 컬렉션) |
| `validateIr`이 유스케이스 IR 모양과 `lineOf` 경로 규칙에 묶임 | 구조 검증은 프로필에서 자동, 규약(`schema`)은 **일반 데이터 모양**에 적용하고 **경로 → 줄 번호를 일반 규칙**으로 매핑 |
| `convertBytes`가 하드코딩된 단계로 변환 | 바인딩을 **실행기**가 해석해 변환(`fields`, `repeat`→`cells`, `diagrams`), 변환 전 `checkProfile` 자동 실행 |
| `previewMapping`이 유스케이스 라벨 고정 | 프로필에서 계산하는 매핑 미리보기 |
| CLI `convert --template --schema` | `convert --profile`(명령 재설계는 I-4) |

## 설계

### md 일반 파서 (D1, D5, D6)
- **항목 영역**: 컬렉션 제목(예: H2)부터 같은 수준 이하의 다음 제목 전까지. 영역 안의 하위 제목은 `under` 이름으로 슬롯과 연결된다.
- **제목 패턴** `'{id} {name}'`: 자리표시자를 이름 붙은 캡처로 바꾼 정규식(앵커 포함)으로 해석한다. 캡처 사이 리터럴은 그대로 일치시키고 각 캡처는 최소 일치(마지막은 나머지 전부)다. 일치하지 않으면 규약 위반(줄 번호 포함).
- **슬롯**(각각 독립으로 읽음): `kv`=영역의 첫 표(1열=키, 2열=값), `records`=머리행을 키로 한 레코드 목록, `list`=첫 목록, `text`=문단, `code`=언어가 같은 코드 블록 전부, `table`=표 원형. `under`가 있으면 그 제목 아래 영역, 없으면 항목 본문(첫 하위 제목 전). 필수(`optional: false`)인데 없으면 위반.
- **하위 컬렉션**(`children`): 영역 안에서 해당 제목 수준을 같은 방식으로 반복해 읽는다.
- 모든 값에 **줄 번호**를 보관한다(`kv`는 키별, 목록·레코드는 행별). 알 수 없는 하위 제목은 경고.
- 결과 데이터 트리의 JSON 모양: `{ meta, <컬렉션>: [{ <캡처...>, <슬롯 키>: 값, <하위 컬렉션>: [...] }] }`. 규약(JSON Schema)은 이 모양에 적용한다(유스케이스 `schema.json`을 이 모양에 맞게 고친다: `flows.main`·`flows.alt` → `main`·`alt`).

### 실행기 (D3, D4, D7)
1. `checkProfile`을 먼저 실행한다. 오류(정책 반영)가 있으면 변환하지 않고 구조화된 오류를 낸다(`ProfileCheckError`).
2. 양식을 열어 `fields`를 채운다(`meta.*` 경로).
3. `repeat`: 컬렉션 항목 수만큼 단위 표를 복제하고(ADR-0012) 항목마다 `do`를 실행한다. `cells`는 라벨 셀 옆 값 셀을 채우고, 값이 없는 라벨은 `unmappedValue`(`clear`)에 따라 처리한다. 값 표기는 `'{id}'` 보간과 `{from, format, default}`(`plain`·`numbered`·`bulleted`·`lines`·`join`).
4. 쪽 나눔·높이 맞춤·그림 폭은 프로필의 `output`을 쓴다.
5. `diagrams`: 코드 슬롯을 렌더(주입된 렌더러)해 단위 뒤에 글자처럼 취급 그림으로 삽입한다. 렌더러가 없으면 `policy.onMissingRenderer`.
6. 저장 후 **자체 검증**(재로드: 누름틀 값, 표 수, 셀 값, 그림 배치, 쪽 나눔, 표 높이, 컨트롤 개수)은 실행기가 기록한 기대값으로 한다.
- 이번에 연결하지 않는 kind(`rows` 등)를 쓴 프로필은 점검 단계에서 거부된다.

### 규약 커버리지 점검 (I-2에서 넘어온 항목)
`schema`(JSON Schema)가 있으면, kv 슬롯의 필수 키가 바인딩(`cells.map` 또는 `'*'`)으로 양식에 채워지는지, 양식의 라벨에 있는지 점검해 `schema-required-unmapped` 경고를 낸다.

### 드라이런 (D8)
`testProfile(engine, {profile, template, exampleMd, ...})`: 예제 md를 같은 경로로 변환해 변환 보고·자체 검증·매핑 대조표를 돌려준다(점검 통과 후 결과가 실제로 맞는지 확인하는 용도, R-03). CLI 명령은 I-4.

## 작업
1. **회귀 기준 만들기(먼저)**: 현재 코드로 `usecase-ok`·`usecase-long`을 변환해 변환 보고와 HWPX 본문 XML의 SHA-256을 골든으로 저장한다(D9).
2. 일반 md 파서·데이터 트리·줄 번호 매핑, 규약 검증 일반화, 유스케이스 `schema.json` 모양 변경.
3. 바인딩 실행기와 값 표기, 정책 적용, 변환 전 `checkProfile`, `ProfileCheckError`.
4. `convertBytes`·Node `convert`·CLI(`--profile`)·`previewMapping`·웹 PoC를 새 API에 맞춘다(웹은 기능 변경 없이 프로필을 불러오도록만 수정, Playwright W1~W8 유지).
5. `testProfile`, 규약 커버리지 점검.
6. 하드코딩 제거 확인: `FIELD_MAP`·유스케이스 라벨·`UseCaseItem`이 코드에서 사라졌는지 시험(문자열 검사)으로 지킨다.
7. 시험: 기존 13개를 새 구조로 이식(기대값 유지, 규약 위반 메시지·줄 번호 유지), **프로필을 바꾸면 매핑이 바뀌는 시험**(라벨·필드·번호 형식·`unmappedValue`·정책을 다르게 한 프로필), 일반 파서 시험(다른 문서 유형 모양: 하위 컬렉션, records·text 슬롯, 제목 패턴 변형), 오류 시험(점검 실패 시 변환 거부).
8. 문서: `md-element-mapping.md`·`doctype-profile.md` 갱신, 검증 기록(S-25 갱신), 결과를 이 문서에 기록.

## 완료 기준
- `pnpm check`·CI 통과, Playwright W1~W8 통과.
- **동작 보존**: 골든과 비교해 유스케이스 변환 결과(보고, `section0.xml` SHA-256)가 같다.
- 코드에 유스케이스 전용 문자열·타입이 없다. 프로필만 바꿔 라벨·누름틀·번호 형식·정책이 바뀐다(시험).
- 규약 위반은 이전처럼 줄 번호와 함께 보고되고, 프로필 점검 오류는 변환을 막는다.

## 확정 보완 (개발자 승인)
- **D6**: 슬롯은 **가능한 한 엄격하게 읽고, 모호하면 위반으로 거부**한다. 읽는 규칙의 변경은 프로필 `version`으로 관리한다. (엄격하게 시작하면 나중에 넓히는 것은 호환되고, 좁히는 것은 호환되지 않는다.)
- **D2**: **구조 검증이 먼저**이고 JSON Schema는 그 위의 추가 제약이다. 둘이 충돌하면 구조 검증 결과가 우선한다.

## 위험
- md 파서를 다시 쓰므로 회귀 위험이 있다 → 골든 + 기존 시험으로 막는다.
- 일반화한 슬롯 규칙이 실제 md 변형(표 앞 설명 문단, 중첩 목록 등)에서 모자랄 수 있다. 위반·경고로 보고하고 I-5(클래스·DB 명세서)에서 보강한다.
- `schema.json`의 데이터 모양이 바뀌므로 기존에 만든 md 규약(있다면)과 호환되지 않는다. 유스케이스 1종뿐이라 영향은 작다.

## 구현 결과
- 완료 기준 충족: `pnpm check`(타입·린트·서식·시험 64건), Playwright W1~W8(스펙 3개) 통과, 골든(변환 보고 + 모든 ZIP 항목 SHA-256, 가짜 렌더러)이 이전 코드의 출력과 같다.
- 구현하며 정한 세부 규칙(코드·시험이 기준):
  - 자체 검증의 셀 값 점검 순서는 매핑 순서가 아니라 **양식의 라벨 순서**다(프로필 항목 순서와 무관한 결과).
  - 반복 단위 이름(그림 대체 텍스트 등)은 제목 패턴의 **첫 캡처 값**이다. 없으면 `<컬렉션>-<번호>`.
  - 하위 컬렉션은 부모 슬롯의 `under`가 가리키는 제목을 항목으로 보지 않는다. `under` 없는 `code` 슬롯은 하위 항목 영역을 뺀 항목 전체에서 읽는다.
  - `cells.value: below`는 라벨 열의 셀 바로 아래 칸을 값 셀로 본다(`labelColumn` 기준).
  - `valueOf`는 전역 이름과 겹쳐 `resolveValue`로 바꿨다.
- 미결: 중첩 목록·표 앞 설명 문단 등 실제 문서 변형에 대한 슬롯 규칙 보강은 I-5(클래스·DB 명세서)에서 한다. 한컴 열림(S-23)은 여전히 미확인이다.

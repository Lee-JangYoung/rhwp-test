# 웹 UI

결정: [ADR-0014](../adr/0014-web-ui-react-mui.md)·[ADR-0018](../adr/0018-web-ui-mui-adopted.md), 구현 기록: [I-8](../07-implementation/I-8-web-ui.md) (MUI로 재구성 완료). UI는 **React + MUI**, 문서 표시는 `@rhwp/editor`(iframe). PoC(`packages/web`, 이식 전 원본은 보관 브랜치 `archive/poc-final`)는 MUI 없이 같은 흐름을 구현했고 [S-18](../06-quality/verification-spike.md)로 확인했다.

등록된 프로필로 **변환·미리보기·다운로드**를 하는 화면. 변환은 브라우저 안에서 수행해 문서를 서버로 보내지 않는다.

흐름: 프로필 선택 → md 업로드/붙여넣기 → 규약 검사 결과 → 변환 → 쪽 미리보기(SVG) → 경고 리포트 → HWPX 다운로드.

- md는 AI가 만들므로 편집기는 텍스트 영역이면 충분하다.
- Vite 번들, `rhwp_bg.wasm`은 정적 자산. 큰 문서는 Web Worker에서 변환하며 `OffscreenCanvas` 폭 측정 가능 여부를 확인한다 [검증 필요 S-13].
- 미리보기 SVG는 sanitize 후 DOM에 넣고, 업로드 크기 상한을 둔다.
- 서버(다수 사용자) 제공 방식은 정책(문서 서버 전송 허용 여부)이 정해진 뒤 정리한다.

## PoC에서 확인된 구성
- 왼쪽: 양식·md 업로드, 자동 미리보기(입력 후 0.8초, Mermaid 제외)와 최종 변환(Mermaid 포함), 규약 위반 줄 번호, 양식 라벨↔md 값 매핑 패널, 변환 보고. 오른쪽: 에디터(양식/결과 전환).
- 에디터는 cross-origin iframe이라 셀 단위 강조·글꼴 주입이 불가해 매핑은 패널로 보여 준다(L-18).
- "변환 결과 저장"(우리가 만든 바이트)과 "에디터 내용 내보내기"(`exportHwpx()`)는 다르다. 자동 미리보기는 결과를 에디터에 다시 불러오므로 에디터에서 고친 내용을 덮어쓴다. 에디터에서 고친 내용은 md로 되돌아가지 않는다(md가 원본).
- 글꼴은 사용자가 올린 파일을 브라우저 메모리에만 두고 Mermaid 그림에 반영한다(서버·저장소로 보내지 않음, S-21). 한컴 글꼴·맑은 고딕 등 상용 글꼴 파일은 저장소에 넣지 않는다(L-12).
- 제한 환경(Artifact 등)에서는 외부 iframe·다운로드가 막힐 수 있다(S-22).

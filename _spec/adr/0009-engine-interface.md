# ADR-0009: 엔진 인터페이스로 라이브러리 교체 가능하게 한다

- 상태: 제안 ([ADR-0005](0005-pin-rhwp-and-isolate-adapter.md)의 "어댑터 격리"를 일반화)
- 날짜: 2026-10-14

## 배경
rhwp는 0.x라 API가 바뀔 수 있고, 후보 라이브러리마다 강점이 다르다(예: HWPX 양식 채움에 강한 XML 패치 방식). 나중에 라이브러리를 바꿀 수 있어야 한다는 요구가 있다. 속도·충실도를 비교한 독립 벤치마크는 찾지 못했다.

## 결정
코어는 `DocumentEngine`/`DocumentSession` 인터페이스에만 의존한다([engine-interface.md](../02-architecture/engine-interface.md)). rhwp 호출은 `engines/rhwp` 한 곳에 둔다. 새 엔진은 공통 왕복 테스트를 통과하면 교체할 수 있다. 인터페이스는 **문서 편집 연산만** 최소로 정의한다.

## 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| rhwp 직접 호출 | 단순 | 교체 시 코어 전체 수정 |
| 여러 엔진을 동시에 지원하는 복합 인터페이스 | 유연 | 지금 요구 대비 과함 |

## 결과
- 엔진 교체 비용이 인터페이스 구현과 공통 테스트로 한정된다.
- 두 번째 엔진은 실제로 필요해질 때(예: S-02에서 양식 보존 문제 확인) 추가한다.

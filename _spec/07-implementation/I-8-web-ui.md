# I-8 웹 UI (React + MUI)

상태: **권장안으로 구현 완료**(개발자 지시: 계획된 기능을 먼저 끝까지 개발하고 평가 후 재설계). 선행: I-3(프로필 변환)·I-5(문서 유형). 결정 근거: [ADR-0014](../adr/0014-web-ui-react-mui.md), [ADR-0018](../adr/0018-web-ui-mui-adopted.md). 화면 명세: [web-ui.md](../05-interfaces/web-ui.md).

## 범위 (사용자가 말한 것만)
등록된 프로필로 **변환·미리보기·다운로드**. 프로필 승인 워크플로·권한·서버 전송은 범위 밖. 프로필 작성·LLM 생성은 CLI·MCP·`@yangsik/author`가 맡고, 웹은 **올린 프로필의 점검 결과를 보여 주는 데까지**만 한다(LLM 호출 없음).

## 결정 사항 (권장안)
| # | 결정 | 근거 |
|---|---|---|
| D1 | PoC 화면을 MUI로 재구성하고 기존 시험용 `data-testid`와 동작을 유지 | 회귀를 시험으로 지킨다 |
| D2 | 내장 문서 유형은 `templates/*/`를 Vite 글롭으로 빌드 때 묶음. 양식(.hwpx)·프로필(.yaml)·규약(.json)을 직접 올릴 수도 있음 | 새 유형을 코드 수정 없이 추가 |
| D3 | 규약 검사는 입력할 때마다 엔진 없이 즉시, 프로필 점검·매핑은 양식이 바뀔 때 | 빠른 피드백 |
| D4 | 매핑·보고·프로필 점검은 접이식 구역(접어도 DOM 유지) | 시험이 숨은 구역의 텍스트도 읽음, 화면 폭 절약 |
| D5 | Web Worker·코드 분할·서버 제공은 하지 않음 | 평가 후 결정(S-13, 서버 정책 미결) |

## 구현 결과
- `packages/web`: `App.tsx`(레이아웃·상태), `panels.tsx`(매핑 대조표·변환 보고·프로필 점검·접이식 구역), `doctypes.ts`(내장 문서 유형 등록부), `browser.ts`(변환 없음).
- 코어 수정: `previewMapping`이 `range` 단위와 `cells.in`을 처리(클래스 명세서의 대조표가 비던 문제, 시험 추가).
- 시험: Playwright W1~W9 통과(W9: 클래스 명세서 전환·변환·틀린 프로필 점검 표시), 웹 빌드·타입 검사. 올릴 파일을 한글 경로의 시험 출력 폴더에 두면 `setInputFiles`가 파일을 읽지 못해 W9는 ASCII 임시 폴더를 쓴다.
- **미검증/이월**: Artifact 같은 제한 환경(S-22), 큰 문서의 Web Worker 변환(S-13), 모바일 화면, 접근성 점검, 에디터(iframe) 로컬 글꼴·외부 호스팅 처리 방침.

# I-A 프로필 생성·검토 (제품 내 LLM 연결)

상태: **결정 확정(2026-10-15), 착수는 I-3 이후**(D13~D20 권장안으로 승인). 개발자 요구: *본 제품에 LLM을 연결해, 양식 파일을 등록한 뒤 프로필을 LLM으로 생성하고 검토하는 기능을 추가한다.*
기존 결정과의 관계: [ADR-0007](../adr/0007-llm-by-host-agent-conversion-llm-free.md)은 "LLM은 호스트 에이전트가 맡고 제품은 LLM API를 부르지 않는다"였다. 이 단계는 **등록(프로필 생성·검토)에 한해 제품이 LLM을 직접 호출**하도록 바꾼다. **변환 경로는 계속 LLM 없이** 동작한다. 승인되면 ADR-0017로 ADR-0007을 부분 대체한다. 호스트 에이전트(MCP) 경로는 그대로 유지하고 두 경로가 같은 도구·점검을 공유한다.

## 선행 조건과 위치
`checkProfile`·양식 분석·`preview_mapping`(I-2)과 프로필 기반 변환 드라이런(I-3)이 있어야 생성 결과를 기계가 검증할 수 있다. 그래서 **I-2 → I-3 → I-A → I-4**를 제안한다(D13).

## 흐름

```
[등록] 양식(HWPX) + (선택) 예제 md
   │ ① 분석(프로그램)    analyzeTemplate → 사실 JSON (표·라벨·머리행·누름틀·책갈피)
   ▼
   │ ② 생성(LLM)         사실 JSON + 가이드 + 스키마 → 프로필 초안 (도구 호출로 사실을 다시 조회)
   ▼
   │ ③ 자동 점검 루프    checkProfile 오류(+후보) → LLM이 수정 → 반복 (최대 N회)
   ▼
   │ ④ 드라이런          예제 md로 변환 → 자체 검증 → 매핑 대조표·쪽 미리보기
   ▼
   │ ⑤ 검토 보고서       결정론적 커버리지 + LLM의 근거 설명
   ▼
[사람] 프로필 파일(YAML)과 보고서를 보고 일부를 고친다 → `check`로 재점검 → git 커밋
```

- ①·③·④와 보고서의 커버리지는 **프로그램**이 한다(결정적). LLM은 ②와 ③의 수정, ⑤의 근거 설명만 맡는다.
- 사람은 프로필 YAML 파일을 직접 고친다. 도구는 사람이 고친 파일을 다시 쓰지 않는다. 승인 워크플로·권한·감사 로그는 범위 밖이다.

## 환각을 줄이는 장치 (I-2 설계 원칙 7과 같은 도구 집합 사용)
- LLM에 줄 것은 **사실 JSON**이다. LLM은 도구(`analyze_template`, `list_kinds`, `get_guide`, `check_profile`, `preview_mapping`)로 양식·어휘를 다시 조회할 수 있고, 프로필의 위치·라벨이 분석 결과에 없으면 `checkProfile`이 거부한다.
- 최종 프로필은 **JSON Schema에 맞는 구조화 출력**으로 받아 YAML로 직렬화한다(검증된 `kind`만 허용).
- 가이드와 예제는 코드에서 생성·시험된 것만 준다. 점검을 통과하기 전에는 초안을 확정하지 않는다.

## 구성
- 새 패키지 `@yangsik/author`: LLM 의존(`@langchain/core`)은 **여기에만** 둔다. `@yangsik/core`는 계속 LLM 없음.
- LLM은 포트(인터페이스) 뒤에 둔다: `LlmClient`(메시지 전송, 도구 호출 루프, 구조화 출력, 사용량). 1차 구현은 LangChain 채팅 모델 어댑터(제공자 무관)이고, 시험은 **가짜 클라이언트**(녹화 응답)로 LLM 없이 돈다. 실제 호출 시험은 API 키가 있을 때만 실행(CI 제외).
- 진입점: 코어 함수 `generateProfile(...)`, CLI `profile generate`·`profile review`(CLI는 I-4에서 명령 확정), 웹 UI(후순위).

## Claude를 쓸 때의 방침 (공식 SDK 문서 기준, 2026-10 확인; 다른 제공자는 해당 문서 기준)
- 모델: 기본 `claude-opus-5-5`, 설정으로 변경 가능. thinking은 항상 켜져 있고(`{type:"adaptive"}` 또는 생략), 깊이는 `output_config.effort`로 정한다(이 모델의 기본은 `medium`이라 `high`를 명시).
- 강제 도구 선택(`tool_choice` any/tool)은 이 모델에서 400이라 쓰지 않는다. 도구는 `auto` + `strict: true`, 최종 프로필은 `output_config.format`(구조화 출력)으로 받는다. 샘플링 파라미터·prefill도 쓰지 않는다.
- 긴 입력·출력이라 스트리밍을 쓰고, **정적 부분(가이드·스키마·`kind` 설명)을 프롬프트 캐시 접두부**로 두어 반복 호출 비용을 줄인다. 안전 분류기 거절(`stop_reason: "refusal"`) 처리와 서버 측 폴백(`fallbacks`) 사용 여부를 코드에 명시한다.
- 인증은 SDK 기본(환경변수 `ANTHROPIC_API_KEY` 또는 `ant auth login` 프로필). 키는 저장소·프로필 파일에 쓰지 않는다.
- 비용은 호출당 입력 수만~수십만 토큰 × 반복 횟수로 추정되며 실측하지 않았다 [검증 필요]. 생성 기록에 토큰 사용량을 남긴다.

## 라이브러리 선정 (조사: npm 레지스트리, 2026-10-15)

개발자 요구: **어떤 LLM이든 사용할 수 있어야 하며, LangChain 사용을 권장.** 이에 따라 제공자 비종속 설계로 바꾼다.

| 후보 | 버전·라이선스 | 성격 | 판단 |
|---|---|---|---|
| **LangChain.js** — `@langchain/core` + 제공자 패키지 | core 1.2.17 · MIT · Node ≥20 | 제공자 공통 채팅 모델 인터페이스(`BaseChatModel`), 도구 바인딩, 구조화 출력, 메시지·사용량 형식 | **채택(개발자 권장)**. 제공자 패키지: `@langchain/anthropic` 1.5.12, `@langchain/openai` 1.6.2(Node ≥22), `@langchain/google-genai` 2.3.2, `@langchain/aws` 1.4.6(Bedrock), `@langchain/ollama` 1.3.0(로컬) — 모두 MIT |
| `@anthropic-ai/sdk`(공식) | 0.134.0 · MIT | Claude 전용 | **보조**. LangChain 경유 Claude 호출에 문제가 확인될 때만 쓰는 직접 어댑터(아래 위험). `@langchain/anthropic`은 이 SDK(`^0.122.0`)에 의존한다 |
| Vercel AI SDK | 7.0.140 · Apache-2.0 | 제공자 추상화 | 대안으로 보류(LangChain이 요구를 충족하는 한 쓰지 않음) |
| Claude Agent SDK | 0.3.300 · 라이선스 별도 | Claude Code 라이브러리 | 제외(내장 파일·쉘 도구, 라이선스) |
| `@modelcontextprotocol/sdk` | 1.32.1 · MIT | MCP 서버/클라이언트 | LLM 호출과 무관, D12의 MCP 서버용 |

- **쓰는 범위**: `@langchain/core`의 채팅 모델 인터페이스·메시지·도구 바인딩·구조화 출력만 쓴다. 체인·에이전트(`langchain`), `langgraph`, 벡터·검색 기능은 쓰지 않는다(점검 루프는 우리 코드로 짧게 돌린다).
- **제공자는 선택 의존성**: `@yangsik/author`는 `@langchain/core`에만 의존하고, 제공자 패키지는 사용자가 필요한 것만 설치한다(선택적 peer). 사용할 모델은 설정으로 고른다(`provider`, `model`, 키·엔드포인트는 환경변수). 호출 측이 `BaseChatModel`을 주입할 수도 있어, LangChain이 지원하는 제공자는 어느 것이든 쓸 수 있다.
- **우리 `LlmClient` 포트는 유지**한다(얇게): `author` 내부에서 LangChain 타입이 퍼지지 않게 하고, 시험용 가짜 클라이언트와 필요 시 직접 어댑터(Claude SDK)를 같은 포트로 끼운다.
- **새로 들어오는 의존성**: `@langchain/core`가 `zod`(필수), `langsmith`, `js-tiktoken`, `@cfworker/json-schema` 등을 가져온다(설치 크기 약 7.6 MB). `langsmith`는 추적 기능용이다. **추적은 끈다**(관련 환경변수를 설정하지 않으며, 문서에 명시. 켜면 프롬프트가 외부 서비스로 간다) [검증 필요: 기본값이 꺼져 있는지 확인].
- **버전**: pnpm 12 공급망 정책을 풀지 않는다. 위 버전은 모두 배포 후 1일 이상 지났다. 정확히 고정하고, 갱신은 최신 안정 버전을 확인한 뒤 한다.

### 제공자 비종속 설계: 능력 등급
모든 모델이 도구 호출·구조화 출력을 같은 품질로 지원하지는 않는다. 그래서 모델의 능력에 맞춰 **세 등급**으로 동작하고, 어떤 등급이든 **결과는 같은 `checkProfile`·드라이런으로 검증**한다(품질 게이트가 제공자에 의존하지 않는다).

| 등급 | 조건 | 방식 |
|---|---|---|
| A | 도구 호출 + 구조화 출력 지원 | 도구로 사실을 조회하며 구조화 출력으로 프로필 생성 |
| B | 구조화 출력만 지원 | 분석 사실 JSON을 프롬프트에 모두 넣고 구조화 출력으로 생성 |
| C | 둘 다 불가(일반 텍스트 모델) | 프롬프트에 사실·스키마·예제를 넣고 JSON 텍스트를 받아 Ajv로 검증, 오류를 되돌려 수정(오류 시 재시도) |

등급은 설정으로 지정하거나(`capability: A|B|C`) 실행 전 **능력 점검 호출**로 판정한다. 모델 품질이 낮으면 점검 통과까지 반복이 늘거나 실패할 수 있고, 이때는 현재 초안과 남은 오류를 보고한다(D18).

### LangChain 경유 Claude 사용 시 주의 [검증 필요, 착수 전 스파이크]
- Claude Opus 5.5는 강제 도구 선택(`tool_choice` any/tool)과 샘플링 파라미터(`temperature` 등) 지정이 400이다. 구조화 출력을 **강제 도구 호출**로 구현하는 래퍼 기본 동작이나 기본 샘플링 값이 이 모델에서 실패할 수 있다.
- adaptive thinking, `effort`, 프롬프트 캐시 지점, `fallbacks`가 LangChain 래퍼를 통해 전달되는지 확인하지 못했다.
- **스파이크(I-A 착수 첫 작업)**: LangChain으로 Claude(`claude-opus-5-5`), OpenAI 호환 모델, 로컬 모델(Ollama)에 대해 ① 도구 호출 ② 구조화 출력 ③ 스트리밍 ④ 사용량 조회가 되는지, 어느 능력 등급이 되는지 확인해 [verification-spike.md](../06-quality/verification-spike.md)에 기록한다. 이 환경에는 API 키가 없어 지금은 실행하지 못했다. 문제가 확인되면 Claude는 직접 어댑터를 쓴다.

## 데이터 전송 (민감 정보)
양식·md의 내용이 외부 LLM 제공자로 전송된다. 기본 정책 제안: **HWPX 파일 자체는 보내지 않고** 분석 사실 JSON(라벨·표 구조·누름틀 이름)과, 사용자가 지정한 예제 md만 보낸다. 보내기 전에 **전송될 내용을 미리 볼 수 있는 옵션**(`--print-prompt`)을 제공하고, 전송 허용 여부를 명시 옵션으로 받는다. 서버(다수 사용자) 정책은 별도 미결이다.

## 작업 (I-A 착수 시)
1. `@yangsik/author` 패키지, `LlmClient` 포트, Anthropic 구현, 가짜 클라이언트.
2. 생성 루프(도구 호출 → 구조화 출력 → `checkProfile` → 수정, 최대 N회, 비용 상한).
3. 드라이런 연결과 검토 보고서(JSON + 사람이 읽는 Markdown).
4. 프롬프트·가이드 버전 관리, 생성 기록.
5. 시험: 가짜 클라이언트로 루프·종료 조건·오류 복구, 잘못된 초안이 점검에서 걸러지는지, 전송 내용 미리보기. 실제 호출 시험(키 있을 때만).
6. 품질 평가: 합성 양식 몇 종에 대해 "점검 통과율, 커버리지, 드라이런 성공"을 측정해 [verification-spike.md](../06-quality/verification-spike.md)에 기록(R-03).
7. 문서: ADR-0017, [doctype-profile.md](../04-conversion/doctype-profile.md)에 생성·검토 절차, 보고서 형식.

## 완료 기준
- 합성 유스케이스 양식과 예제 md로 `generateProfile`이 점검과 드라이런을 통과하는 프로필과 검토 보고서를 만든다(가짜 클라이언트 시험 + 실제 호출 1회 기록).
- 일부러 틀린 초안(없는 라벨, 잘못된 `kind`)을 LLM이 점검 오류를 보고 고치는 루프가 시험으로 확인된다.
- 전송 내용 미리보기와 비전송 옵션이 동작하고 HWPX 바이너리는 전송되지 않는다.
- `@yangsik/core`에 LLM 의존이 없음을 시험으로 보장한다.

## 위험
- LLM 출력은 비결정적이다(이 모델에서는 샘플링 설정도 불가). 그래서 결과를 점검·드라이런·보고서로 검증하고 사람이 확인하는 지점을 남긴다.
- 양식 내용의 외부 전송은 정책이 필요하다(D15). 폐쇄망에서는 쓸 수 없다.
- 합성 양식으로 품질을 평가하므로 실제 SI 양식에서의 품질은 I-6 이후에 알 수 있다 [검증 필요].

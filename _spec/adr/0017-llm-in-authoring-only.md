# ADR-0017: 등록(프로필 생성·검토)에서만 제품 내 LLM을 쓴다

- 상태: 채택. [ADR-0007](0007-llm-by-host-agent-conversion-llm-free.md)을 부분 대체한다.
- 날짜: 2026-10-15

## 배경
ADR-0007은 "LLM은 호스트 에이전트가 맡고 제품은 LLM API를 부르지 않는다"였다. 개발자 요구로, 양식을 등록한 뒤 **프로필을 LLM으로 생성·검토하는 기능을 제품에 넣는다**. 어떤 LLM이든 쓸 수 있어야 하고 LangChain 사용이 권장됐다.

## 결정
- **등록 단계(프로필 생성·검토)에서는 제품이 LLM을 직접 호출**한다. **변환 경로는 계속 LLM 없이** 동작한다(ADR-0007의 변환 부분은 유지).
- LLM 의존은 새 패키지 `@yangsik/author`에만 둔다. `@yangsik/core`는 LLM 없음.
- 라이브러리는 LangChain.js(`@langchain/core` + 제공자 패키지 선택 설치), 제공자 비종속(능력 등급 A/B/C). 필요 시 Claude 직접 어댑터를 예비로 둔다.
- 생성 결과는 항상 같은 `checkProfile`·드라이런으로 검증한다. 호스트 에이전트(MCP) 경로도 유지하며 같은 도구·점검·가이드를 공유한다.
- 양식·md 내용이 외부 LLM으로 전송되므로 HWPX 파일은 보내지 않고 분석 사실 JSON과 지정한 예제 md만 보낸다(전송 미리보기·명시 허용). 승인 워크플로·권한·감사 로그는 범위 밖이다.

## 대안
| 대안 | 단점 |
|---|---|
| 호스트 에이전트만(ADR-0007 유지) | 제품 단독으로 등록 자동화 불가 |
| 변환에도 LLM | 비결정적, 비용·보안 부담 |

## 결과
상세 계획: [I-A](../07-implementation/I-A-profile-authoring.md). 착수 전 스파이크로 LangChain 경유 제공자별 동작을 확인한다.

# ADR-0007: LLM은 호스트 에이전트가 담당하고 변환은 LLM을 쓰지 않는다

- 상태: 제안
- 날짜: 2026-10-14

## 배경
등록 단계의 의미 해석(표의 의미, 키 명명, 반복 단위 추정)에는 LLM이 유용하다. 반면 변환과 검증은 재현성과 보안이 중요하다. md는 AI가 생성한다.

## 결정
1. **변환·검증 경로에는 LLM을 쓰지 않는다**(결정적 프로그램).
2. 등록 단계의 LLM 해석은 **호스트 에이전트(MCP 클라이언트 등)가 수행**한다. 우리 프로그램은 분석 결과·지침을 제공하고, 에이전트가 만든 초안을 **JSON 스키마로 검증**해 조립·저장한다. 프로그램이 LLM API를 직접 호출하지 않는다.
3. LLM이 만든 결과는 프로필 파일로 고정(커밋)하고 사람이 승인한다.

## 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| 프로그램이 LLM API 직접 호출 | 독립 실행 | API 키 관리, 오프라인 불가, 문서 외부 전송 |
| 변환에도 LLM 사용 | 유연 | 비결정적, 비용, 검증 곤란 |

## 결과
- 키 관리가 필요 없고, 문서는 사용자가 이미 쓰는 LLM 범위에서만 다뤄진다.
- LLM 없이 CLI/웹만으로 변환이 가능하다. 등록 보강은 에이전트가 있을 때 편하다.

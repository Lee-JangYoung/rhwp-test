# 기능 평가와 재설계 제안 (I-A~I-8 완료 시점, 2026-10-15)

개발자 지시: 계획된 기능을 먼저 끝까지 개발하고, 평가한 뒤 재설계한다. 이 문서는 **평가와 제안**이며 재설계 착수는 승인 후다. 측정·재현 사실은 [verification-spike.md](../06-quality/verification-spike.md) S-28·S-29가 단일 출처다.

## 2. 성능 (S-28)
항목 수에 대해 **초선형**이다(유스케이스 20항목 3초 → 100항목 57초). 엔진 호출을 분리 측정한 결과, 표 위치 조회(`topTables`)는 무시할 수준이고 지배 비용은 **문서가 커질수록 호출당 비용이 커지는 편집 호출**이다: `setCellText`(호출당 9 ms → 39 ms)와 `fitTableHeights`(표 100개에서 68 s). 독립 검토가 의심한 `refOf` 비용은 측정으로 반박됐다. 한 번의 변환이 수십 초 걸리면 웹(UI 멈춤)·MCP(도구 호출 시간 제한)에서 쓰기 어렵다.

## 3. 결함 (독립 검토 2건, S-29)
**A. 안전·조용히 틀림 — 즉시 수정 대상**
- MCP `convert_md`: 존재하지 않는 중간 폴더 + `..`로 허용 폴더 밖에 쓰기, 심볼릭 링크·임의 확장자 덮어쓰기, 프로필의 template/schema 경로를 가드 없이 읽음(다른 도구는 막음), `--root=경로`/값 없는 `--root`를 무시하고 현재 폴더 전체 허용.
- md 제목 값이 Mermaid 중간 파일 이름이 되어 경로 탈출(`../`), 병렬 변환이 같은 `.work`를 공유해 다른 문서의 그림이 들어감.
- Mermaid(Chromium)가 md 내용으로 외부 요청을 보냄(데이터 반출·SSRF 통로). 문서의 "로컬 처리"와 불일치.
- LangChain 추적 환경변수(`LANGSMITH_TRACING` 등)가 있으면 프롬프트가 LangSmith로 감(`allowSend` 밖).
- 생성 프롬프트의 `excludes: 양식 본문 전체`가 사실과 다름(본문 문단 앞 60개·표 샘플이 전송됨). `profile generate --out`이 승인된 프로필을 경고 없이 덮어씀. LLM 응답 검증 부재(`rationale`·YAML 별칭)로 한 번의 이상한 응답이 전체를 중단, 비용 상한 느슨(off-by-one, NaN 입력).
- 데이터: `table.index`가 점검(양식 기준)과 실행(복제·삭제 후 기준)에서 다름, 같은 표를 채우는 `cells` 두 개가 첫 값을 지움, 라벨·머리글 중복 시 하나만 채움(조용), front-matter `1.10`→`1.1`, 선택 슬롯이 없으면 바깥 범위의 같은 이름 값이 끼어듦, 세로 병합 견본 행의 값 누락(조용), 양식에 원래 있던 그림이 자체 검증을 항상 실패시킴, repeat 밖 `cells` 뒤 `remove`가 거짓 검증 실패.

**B. 점검과 실행의 불일치**: `remove` 뒤 같은 라벨/표를 쓰는 바인딩, 60자 넘는 라벨(분석이 잘라 냄), `table.text`(점검은 앞 12칸만), 레코드 키의 `.`(`No.`), 3단 중첩의 `diagrams` 위치.
**C. 문서와 동작 불일치**: CLI 입력 오류(없는 파일)가 exit 3, 여러 md 중 하나가 없으면 전체 중단·`--report` 미작성, 같은 이름 md가 같은 출력으로 덮어씀, MCP가 문자열 예외를 `isError`로 못 바꿈.

**수정 현황 (제안 1단계, 이 PR)**: A·C와 B 중 아래를 수정하고 회귀 시험 32개를 추가했다(수정 전에는 대부분 실패함을 확인).
- MCP: 경로 정규화 후 검사, 쓰기는 `.hwpx`만·링크 대상 확인, `convert_md`는 프로필의 template/schema도 가드를 거침(코어 `convert()`를 쓰지 않음), 값 없는/`=` 형식 `--root` 처리(잘못된 인자는 종료), 문자열 예외를 `isError`로, `list_doctypes`·`get_md_template`의 링크 처리.
- 변환 코어: 호출마다 임시 작업 폴더(동시 실행 격리), Mermaid 파일명은 해시가 붙은 안전한 이름, Mermaid는 `securityLevel: strict` + 네트워크 차단(루프백 포함)으로 렌더(서버가 받은 요청 0 시험), 양식에 있던 그림·떠 있는 그림을 검증 기준에서 제외, 바깥(repeat 밖) 표는 같은 객체로 추적(양식 표 번호 기준 `index`), 여러 `cells`가 같은 표를 채울 때 앞 값을 보존, 라벨·머리글 중복은 `label-ambiguous` 오류, 세로 병합 견본 행은 `merged-cell` 오류, 조상 문맥 전체에 복제 표 반영, 선택 슬롯 부재를 빈 값으로 고정, front-matter는 문자열로 보존, `No.` 같은 키, `constructor`·`toString` 키, 라벨·머리글 300자까지 보존, `table.text`는 전 셀 기준.
- author: 모델 응답의 YAML·`rationale` 검증과 예외 흡수, 모델 호출 실패 시 `llm-error`로 기록 보존, 도구 반복 중 토큰 상한·병렬 도구 호출 8개·사용량 0/NaN 어림, 프로필의 `template`/`schema`는 고정 이름만, `allowSend === true`, 추적 환경변수가 켜져 있으면 클라이언트 생성 거부(`allowTracing`으로 명시 허용), 전송 범위 문구 정정과 전체 셀 텍스트 비전송.
- CLI: 입력 오류는 종료 코드 1, 여러 md 중 일부 실패해도 요약·보고서 기록, 같은 이름 md 거부, `profile generate`의 숫자 옵션 검증과 기존 산출물 보호(`--force`).
- **남은 것**: `remove` 뒤 같은 라벨·표를 쓰는 바인딩, `fields`에 객체 값 매핑은 I-9(계획 컴파일)에서 다룬다. 성능(R1)은 3단계.

## 5. 제안 순서와 결정 요청
1. **즉시 수정(§3-A·C, R5·R6·R7)**: 설계 결정 없이 고칠 수 있는 결함. 시험을 먼저 추가해 재현을 고정한다.
2. **R2(계획 컴파일) + R3·R4**: 한 단계(I-9)로. 점검·실행 불일치 클래스를 없앤다.
3. **R1**: (a)로 계측·순서 재배치를 먼저 하고 효과를 보고 (b)의 필요를 판단한다.
4. 한컴 확인(S-23)·실제 양식·실제 모델 호출은 사람의 작업이며 위 결과와 병행한다.

**개발자 결정이 필요한 것**: (1) 위 순서와 범위 승인, (2) R1(b) XML 직접 편집 엔진을 지금 설계할지 R1(a) 결과 후 판단할지, (3) R3의 엄격화로 md 호환이 좁아지는 것을 받아들일지, (4) 보안 결함을 이 PR(#6)에서 같이 고칠지 별도 PR로 낼지.

# I-9 실행 계획(점검=변환)과 엄격한 md 읽기

상태: **권장안으로 구현 완료**(평가 2단계, [evaluation-2026-10.md](../08-evaluation/evaluation-2026-10.md) §4 R2·R3·R4). 개발자 승인: 순서·범위 승인, md 엄격화로 호환이 좁아지는 것을 수용("진행").

## 문제
점검(`check.ts`)과 변환(`convert.ts`)이 위치 지정을 각자 해석해 결과가 갈렸다: 점검은 통과하는데 실행에서 평문 오류(remove한 표를 뒤에서 씀), 같은 `index`가 다른 표를 가리킴, 점검이 유효한 프로필을 거부(긴 라벨, `table.text`). md는 제목 수준·철자 오류에서 내용을 조용히 버렸다.

## 결정 (권장안)
| # | 결정 | 근거 |
|---|---|---|
| D1 | **점검이 풀어낸 표 위치를 `Plan`으로 돌려주고 변환은 그것만 쓴다**(바인딩 경로 → 문맥 안 위치: `tables`, `units`, `removeTables`). 실행은 위치 지정을 다시 해석하지 않는다 | 해석 코드가 한 곳뿐이면 점검/실행 불일치가 생기지 않는다 |
| D2 | 문맥 안 위치는 복제본 자신의 표 목록(`slots`, 양식 순서 고정)을 가리키고, 안쪽 repeat이 만든 복제 표는 별도 목록(`all`, 쪽 나눔·그림 위치용)에만 넣는다 | 안쪽 복제로 위치가 밀려도 계획의 위치가 유효 |
| D3 | `remove`·`repeat.onEmpty: remove`는 조건부라 **뒤에서 그 표·라벨을 쓰면 `target-removed` 오류** | 순서 문제를 점검 때 잡는다 |
| D4 | md: 읽지 않는 제목은 **위반**(이전 경고), 읽는 슬롯이 없는 코드 블록은 위반, 슬롯 없는 문단은 경고, kv 3열 이후는 위반. `<br>`은 줄바꿈, 느슨한 목록 항목의 문단은 줄로 이어붙임 | 데이터가 조용히 사라지지 않게. LLM이 틀린 md를 쓰면 줄 번호와 함께 되돌려 고친다 |
| D5 | 같은 영역의 선택 슬롯이 앞에 있는 같은 종류 슬롯 여러 개는 `slot-ambiguous` | 표·목록이 나오는 순서로 슬롯에 대응하므로 구분 불가 |
| D6 | `fields`: 목록은 쉼표로 이어 넣고 객체는 `invalid-value` | `[object Object]` 방지 |

## 구현 결과
- `checkProfile`이 `plan`을 돌려주고 `convertBytes`가 그것을 쓴다(실행기의 위치 해석 코드 제거). 새 오류 코드: `target-removed`, `slot-ambiguous`.
- `markdown/read.ts`: 위 D4. 시험은 기존 경고 기대를 위반으로 갱신.
- 시험 9개(`test/plan-strict.test.ts`): 지울 수 있는 표·라벨을 뒤에서 쓰는 3가지 형태, 제목 수준 오류, 코드·문단, kv 3열, `<br>`·느슨한 목록, 슬롯 모호, fields 목록·객체.
- **영향**: md 호환이 좁아진다(예: 틀린 제목 수준·미지의 제목이 위반). 프로필 `version`은 올리지 않았다(0.x, 내장 유형은 시험으로 통과 확인). 실제 양식·md 수집 후 완화가 필요한지 평가한다.
- 이월: `table.text`가 긴 문자열인 경우 등 양식 사실의 잘림 경계, `paragraphs`의 문단 복제.

# 제약과 위험

| # | 항목 | 내용 | 영향 | 대응 |
|---|---|---|---|---|
| L-01 | API 불안정 | 0.x 단계, 편집 API 시그니처 변경 가능 | 업그레이드 시 깨짐 | 버전 고정, 어댑터 격리, `*Ex` 우선 |
| L-02 | 글자 폭 | rhwp README는 호스트의 `measureTextWidth` 제공을 요구하나, Node 시험에서는 호출되지 않았음(폭 계산 경로 불명) | 쪽수·줄바꿈이 한컴과 다를 수 있음 [검증 필요 S-11]. `@rhwp/editor` README는 조판이 내장 폰트 메트릭 기준이라 화면 글꼴을 바꿔도 쪽수는 변하지 않는다고 설명 | 글꼴·폭 계산 경로 확인, 쪽수 비교 테스트 |
| L-03 | 조판 차이 | 복합 문자 shaping, 옛한글 등은 Canvas2D 폴백 | 한컴과 레이아웃 차이 | 한컴 뷰어 수동 확인 절차 |
| L-04 | HWPX 저장 | 구버전(0.7.3) 제한 언급이 있었으나 0.8.7 단순 문서에서는 재현 안 됨. 양식 요소 보존·비표준 파일(`META-INF/rhwp-hwp5-origin`)의 한컴 열림은 미확인 | HWPX 출력 신뢰도 | 실제 양식으로 검증(S-02) |
| L-05 | HML | 검증된 구조만 지원, 미지원 시 저장 차단 | HML 출력 비권장 | 범위 제외 |
| L-06 | 빈 문서 스타일 | `createEmpty()` 문서의 스타일 목록이 비어 있음 | 코드만으로 양식 불가 | 양식 파일 필수 |
| L-07 | 한컴 호환 | rhwp 재로드 성공 ≠ 한컴 정상 열림 | 현장 제출 시 문제 | 한컴 뷰어 수동 확인 |
| L-08 | 에디터 기본 URL | `@rhwp/editor` 기본 `studioUrl`이 GitHub Pages | 폐쇄망/오프라인 불가 | 자체 호스팅 `studioUrl` |
| L-09 | 반환 형태 | 편집 API가 JSON 문자열 반환(`exportHwp(x)`는 `Uint8Array`로 확인됨) | 파싱 오류 | 엔진에서 `ok` 검사·정규화 |
| L-10 | PDF/PNG | PNG는 `native-skia` 빌드 필요, 한컴 PDF와 결과 차이 | 미리보기 정확도 | 미리보기는 SVG 기본 |
| L-11 | 빈 문서 호환 | `createEmpty()` 문서는 구역 정의·단 정의가 없어 실제 HWP와 다름(rhwp 문서 주석). `createBlankDocument()`는 이를 가진 문서를 만듦 | 한컴 호환 위험 | 양식 또는 `createBlankDocument()` 기반으로 작업(S-15) |
| L-12 | 글꼴 | HWPX는 글꼴 **이름만** 저장(파일 미포함, 7개 언어 카테고리별 지정). 번들 템플릿은 함초롬돋움·함초롬바탕 사용. 실행 환경에 없으면 대체 글꼴(미리보기 SVG는 폴백 체인). 줄 배치(`lineseg`)가 파일에 저장됨. 함초롬 글꼴의 공식 라이선스는 미확인 | 미리보기와 줄바꿈·쪽수가 한컴과 다를 수 있음, 한컴의 `lineseg` 재사용 여부 미확인 [검증 필요 S-17] | 파일에 글꼴을 넣지 않고 양식의 글꼴명 유지, 실행 환경에 오픈소스 한글 글꼴 설치(Noto·나눔·Pretendard), 리포트에 `fontsUsed`/`fontSubstitutions` 표시, 한컴 글꼴 파일은 라이선스 확인 전 저장소·서버에 넣지 않음 |
| L-13 | 그림 기본 배치 | `insertPictureEx`는 용지 기준으로 떠 있는 개체(`treatAsChar:false`)를 만들어 표를 덮음 | 그림이 엉뚱한 위치에 겹침 | 삽입 직후 `treatAsChar:true`로 변경, 저장 후 검증(S-20) |
| L-14 | 표 저장 높이 | 셀 내용을 바꿔도 표의 저장 높이는 양식의 원래 값으로 남음 | 뒤따르는 그림·문단이 표를 가림 | 셀 높이를 렌더 높이로 설정(`fitTableHeights`), 저장 높이≥렌더 높이를 검증(S-20) |
| L-15 | 표 쪽 나눔 | rhwp 조판은 `pageBreak` 값을 무시하고 "글자처럼 취급" 표를 나누지 않음 | 긴 표가 쪽 아래로 넘침. 한컴 동작 미확인(S-23) | 쪽을 넘는 반복 블록은 떠 있는 표 + `pageBreak`=CELL(adr-0012) |
| L-16 | 손실 보고 | `contentLoss` 보고가 0건이어도 컨트롤이 줄 수 있음(쪽번호 7→4) | 저장 손실을 놓침 | 저장 전후 컨트롤 종류별 개수를 직접 비교(S-19) |
| L-17 | `lineseg` | 변환 산출물의 일부 문단에 줄 배치(`lineseg`)가 비어 스튜디오가 경고(#2527) | 한컴의 처리 미확인 | S-17·S-23에서 확인 |
| L-18 | 에디터 iframe | `@rhwp/editor`는 외부 호스팅(cross-origin) iframe: 셀 단위 강조·글꼴 주입 불가, 문서가 외부 호스팅 페이지에서 처리됨. 다른 사이트 iframe을 막는 제한 환경(Artifact 등)에서는 표시되지 않을 수 있음(S-22) | 웹 UI 설계 | 매핑·검증은 React 패널로 표시, 자체 호스팅 `studioUrl`(L-08) |
| L-19 | 다중 구역 | 구역 1 이후의 표는 문단 번호가 구역 기준이라 구역 0으로 해석하면 실패 | 다중 구역 양식 미지원(표본 40개 중 2개) | 구역 0만 지원, 다중 구역은 분석 단계에서 거부 |
| L-20 | 표 묶음 복제 | 표 묶음(`range`)을 복제할 때 표 사이의 문단(빈 줄·캡션)은 복제되지 않음 | 복제본은 원본보다 표 사이 간격이 좁아 보임(합성 양식에서 확인) | 필요하면 간격을 양식의 표 안(여백)으로 표현. 실제 양식에서 필요가 확인되면 문단 포함 복제를 설계 |
| L-21 | 문단·토큰 치환 범위 | `text`는 문서 전체에 적용(`replaceAll`), `paragraphs`는 본문 문단 하나를 대상으로 함 | repeat 안에서 복제본마다 다르게 채울 수 없음 | front-matter 값에만 사용. 항목별 서술은 표 셀(`cells`)로 표현 |
| L-22 | 여러 표 양식의 표 배치 | 한 문서에 표가 여러 개면 "떠 있는 표"끼리 겹쳐 보여 합성 양식은 "글자처럼 취급"으로 만듦(L-15: 쪽을 넘는 표는 나뉘지 않음) | 긴 목록 표가 쪽 아래로 넘칠 수 있음. 한컴 동작 미확인(S-23) | 합성 양식 한정. 실제 양식은 S-23과 함께 확인 |
| L-23 | HWP 5.0 출력의 조판 차이 | HWPX에서 연 문서를 `exportHwp`로 저장하면 rhwp가 HWPX→HWP 어댑터를 적용한다. 내용(표·셀·필드·그림)은 같지만 '글자처럼 취급' 표가 쪽을 넘는 양식은 HWPX 재로드 1쪽 / HWP 재로드 3쪽처럼 **쪽 수가 달랐다**(키트 04, S-30). 원인은 두 형식 로더의 표 속성 해석 차이로 추정(미조사) | HWP를 한컴에서 열면 쪽 나눔이 HWPX와 다를 수 있음. 변환은 쪽 수 차이를 `notes`로 알리되 막지 않음 | 한컴 확인(S-23)에서 두 파일의 쪽수·표 모양을 비교한 뒤 결정. 기준 출력은 HWPX |
